# requirement 阶段 · PRD — Link World Web 重构（Round 1）

> 状态：completed | 日期：2026-06-07 | Gate：1（设计） | Round：1
> 范围：**只 Web 端**（`packages/web`） | 主题：深蓝金重塑 + 对齐产品文档
> 产出方式：brainstorming（发散）+ office-hours（收敛）协作产出，决策已拷问到可验收条件。

---

## 一、重构目标（What & Why）

把现有 Link World web 端（功能完成度约 80%，业务逻辑层 100% 可复用）做一次**视觉重塑 + 产品文档对齐**：

- **视觉**：从现有「赛博深色」换成「深蓝渐变 + 米白卡片 + 金色点缀」的「The Decentralized Future」高级 Web3 风。
- **功能对齐**：修正「产品文档 vs 现有代码」的差异（数值、缺失页面、规则文案），**仅在纯前端能力范围内**。

**根本约束（甲）**：本轮**只动 web 前端**。后端 API、合约、业务逻辑层（hooks/services/utils/types）一律不动；唯一例外是 `config/constants.ts` 的配置数值。

---

## 二、用户故事（核心用户路径，沿用现状不变）

数字游民 / Web3 用户：连接钱包 → 提供邮箱注册 → 存保证金（≥10u）→ 锁仓获 NFT 流量卡 → 选目的地运营商申请号码 → 用量产生账单 → 钱包支付（含 1.5% 手续费）。

本轮**不改这条主流程的逻辑**，只换皮 + 对齐文案/数值 + 补少量前端降级功能。

## 四、功能对齐清单（甲约束下的前端方案）

### 类①：数值/文案（直接改 `config/constants.ts` + UI 展示）
- `MIN_DEPOSIT_USDT`：`100n * 10n**18n` → **`10n * 10n**18n`**（文档「10u 起」）。
- `PLATFORM_FEE_RATE`：`0.025` → **`0.015`**（文档「1.5% 手续费」）。
- 1.5% 手续费**在「申请号码弹层」（`RegionDetail`）+「支付账单页」（`Billing`/`BillDetail`）明确展示费用明细**。

### 类②：前端降级实现（依赖后端/合约的部分只能做 UI 层）
- **实体 SIM 卡领取**（文档 4.6）：Cards 页新增「SIM 领取」Tab —— 选目的地国家 + 收件信息表单 + 提交；后端无接口 → 提交后 toast 成功 + 写入 `pendingSync`（localStorage），附「全球通 SIM 即将推出」说明。
- **NFT 自动发放**（文档 4.4）：Cards 页移除「Issue Monthly Card (Admin)」按钮，改说明文案「锁仓满 1 个月后系统按保证金额度自动发放流量卡」。
- **锁仓期未到不可提取**（文档 4.4）：Deposit 页 Withdraw 区**加静态提示**「保证金锁仓期 1 个月内不可提取」。做不了动态禁用——`DepositInfo` 仅含 `balance`/`currency`，无锁仓到期字段（属甲约束外）。
- **不可转卖 / 销毁后 30 天有效**（文档 4.4）：Cards 页加规则说明文案；`expiry` 已有展示。

## 五、范围红线（绝不碰）

- ❌ 不改后端 API、不改合约、不改 hooks/services 业务逻辑（仅可改 `config/constants` 数值与 UI 消费色值的方式）。
- ❌ 不改路由结构、不新增底部导航第 6 项。
- ❌ 注册流程保持邮箱不动。
- ⚠️ **方案 X 的代价记录在案**：`components/ui/*`（button/badge/tabs）+ `index.css` oklch 变量是深色主题，X 方案下需**重做明暗体系**（卡内文字深色化、米白卡片配色），这是本轮**最大工作量块**，design / 任务拆解阶段需重点排期。

## 六、验收标准（Acceptance Criteria）

### A. 视觉（机器核查 + 人工核查）
1. 9 个页面 + `layout`/`shared`/`wallet` 组件**全部**应用新主题，无遗漏页（覆盖率 100%）。
2. grep **查无**旧色值残留：`#3b82f6`、`#0a0a14`、`#0f0f1a`、`bg-brand-blue`、`to-brand-purple`、`#8b5cf6`、`#06b6d4`。
3. grep **查无** emoji 当图标残留（🏠📱💰📄🎟️🔔 等全部替换为 lucide）。
4. 色值单一出口：业务组件不再直接吃硬编码 HEX，统一走语义化 token / CSS 变量。
5. `main.tsx` RainbowKit `accentColor`、body 字体冲突（Inter/Geist）一并修正。
6. 卡片为米白/浅色、背景为深蓝渐变、金色仅出现在金额/CTA/激活态/品牌强调。

### B. 功能（人工走查 + test 阶段）
7. `MIN_DEPOSIT_USDT = 10`、`PLATFORM_FEE_RATE = 0.015`，且 UI 显示正确。
8. 1.5% 手续费在申请号码弹层 + 支付账单页明确展示。
9. Cards 页：双 Tab（流量卡 / SIM 领取）；Admin 发卡按钮已移除并替换为自动发放说明；不可转卖 / 销毁后 30 天规则文案到位。
10. SIM 领取表单可填可提交，提交后 toast 成功 + 写入 `pendingSync`。
11. Deposit 页 Withdraw 区有锁仓静态提示。
12. **主流程端到端走通**（注册→存保证金→购买服务→支付账单）在新 UI 下正常，业务逻辑不变 —— **由 test 阶段做端到端走查验收**（如 browse 录屏 / 手动走查）。

### C. 设计细节对齐
13. 金色具体色值（候选 `#D4AF37` 沉稳金 / `#F0C75E` 香槟金）、字体方案（修 Inter/Geist 冲突、是否启用 Orbitron 做金色科技标题）**以 design 阶段产出为准**；本验收只要求「已应用 design 阶段确定的规范」，requirement 不锁像素。

## 七、移交 design 阶段（待决细节）

design 阶段需产出并锁定：
1. **金色色值**（沉稳金 vs 香槟金）+ 金色应用规则（哪些元素、明度/对比度）。
2. **深蓝渐变**精确参数（`linear-gradient(135deg, #0C2340 0%, #1E40AF 50%, ...)` 的完整停靠点）。
3. **米白/浅色卡片**色值 + 卡内文字色阶（主/次/弱文本在浅底上的深色映射）。
4. **字体方案**：修 Inter/Geist 冲突；是否启用 Orbitron 做金色科技标题。
5. **色值出口统一方案**：Tailwind 语义 token 与 oklch CSS 变量如何收敛为单一来源。
6. **lucide 图标映射表**：每处 emoji → 对应 lucide 图标。
7. **缺失原子组件**是否补齐（Card/Input/Dialog），由 design 决定保留/替换 `ui/*`。
8. 9 页 + 组件的新主题视觉稿 / 高保真。
